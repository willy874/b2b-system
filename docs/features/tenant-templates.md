## 背景

佈建新租戶時只會建立權限目錄、系統角色與第一位 super-admin（[`05-tenancy.md`](../architecture/05-tenancy.md) §5）。之後每個客戶都要手動重做一次：
自訂角色、群組結構、系統設定、事件開關、標籤組、Webhook 訂閱。另外：

- 客戶想要一個 **沙盒** 先試新的角色設計或整合，現在只能請平台另開一個空的租戶再手動照抄。
- 同一家集團的多個子公司（多個租戶）要一致的設定，沒有方法同步。

[`import-export.md`](./import-export.md) 明列「跨租戶搬移」不做；這份提案只處理 **設定**，不搬業務資料。

## 範圍

| 做 | 不做（這一版） |
| --- | --- |
| 匯出租戶的設定成範本：自訂角色（含權限鍵）、群組（不含成員）、系統設定覆寫、通知事件開關、標籤組與標籤 | 使用者、檔案、稽核等業務資料 |
| 建立租戶時選一個範本套用 | 持續同步（範本改了，已套用的租戶跟著改） |
| 對既有租戶套用範本：先預覽差異、確認後套用 | Webhook 的密鑰、外部 IdP 的 client secret（不出現在範本裡） |
| 「從這個租戶建立沙盒」：以它的設定建立新租戶 | |

## 使用者故事

**作為平台營運，我希望新客戶開通時直接套用「零售業標準範本」，以便客戶不必從零設計角色。**

- **Given** 平台上有範本「零售業標準」
- **When** 我建立租戶並選這個範本
- **Then** 佈建完成後租戶已有範本裡的角色、群組、標籤與系統設定；第一位 super-admin 照常收到啟用信

## 初步構想

- 範本格式：版本化的 JSON（`schemaVersion`），每一段由擁有者模組產生與套用（`TemplateSection { key, export(), diff(), apply(tx) }`，在 `onModuleInit` 登記）。
- 儲存：平台 DB 的 `tenant_templates`（平台管理）；租戶也可以下載自己的範本檔（見開放問題 1）。
- 套用：佈建工作的 ③ 之後多一步；對既有租戶走 [`import-export.md`](./import-export.md) 的「驗證 → 預覽 → 套用」。
- 反提權：套用由平台執行，不經租戶使用者，但角色的權限鍵仍要在目錄裡；被移除的權限鍵略過並列在報告。
- 稽核：租戶稽核記每一個被建立／修改的實體（actor 為 `system`、metadata 帶範本 id）；平台稽核 `tenant.applyTemplate`。

## 開放問題

1. 租戶管理者能不能自己匯出／匯入範本（例：把正式租戶的角色搬到沙盒）？那需要兩個租戶之間有關聯。
2. 套用到既有租戶時，同名的角色是覆寫、略過還是改名？
3. 沙盒租戶要不要有特殊標記（不寄信、Webhook 預設停用、定期清除）？
4. 範本與 [`tenant-plans.md`](./tenant-plans.md) 是否合併？（方案管 feature 與參數，範本管租戶內的設定）
