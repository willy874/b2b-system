## 使用者故事

**作為流程設定者，我希望從範本開始、隨時看到整條流程的樣子，以便不用先讀規格才敢按儲存。**

- **Given** 「使用者註冊」還沒有流程
- **When** 我按「設定流程」
- **Then** 先選範本（「申請人的主管 → 管理員」「指定的人單關」「從空白開始」）；編輯時上方有一行摘要「申請 → 合作夥伴初審（網域 = partner.example.com 時）→ 系統管理員（1 人）→ 建立帳號」；修改後試算自動更新；儲存時提示「進行中的 2 筆照舊版本處理」

## 初步構想

### 第 3 批：流程設定的引導

| 項目 | 做法 |
| --- | --- |
| 範本 | 「設定流程」（還沒有流程時）先開範本選擇：「申請人的主管」「申請人的主管 → 指定角色」「指定的人」「從空白開始」。範本是前端常數（`features/approval-flow/templates.ts`），只產生草稿；依 handler 的 `flow.requester`（匿名的不能用主管）與 `assigneeKinds`（組織、群組未啟用）過濾，不能用的範本不列出。需要指定對象的範本（角色、人）在草稿裡留空並標示「請選擇」。不做租戶自訂範本（D6） |
| 流程摘要 | 編輯頁頂部一列「申請 → 關卡 1 → 關卡 2 → 結果」的橫向摘要，條件與同意數以小字附在節點下；點節點捲到該關卡並展開 |
| 精簡卡片 | 關卡預設收合成一行（「第 1 關・合作夥伴初審・指定使用者：王小明・1 人・1 個條件」），點開才是表單；新增的關卡、有錯誤的關卡自動展開 |
| 概念說明 | 「需要幾人同意」旁的說明（指定人數＝任 M 人同意即通過；全部＝會簽）；最後一個會執行的關卡標示「這一關的審核者還需要『建立使用者』權限，沒有的人不會成為審核者」。`GET /approval-flows/:type` 多帶 `requiredPermissions`（權限鍵），前端以權限目錄的語系顯示名稱 |
| 自動試算 | 草稿變動後 debounce 500ms 自動試算（草稿不完整時不送，維持現在的提示）；條件欄位預填 `fields[].example`（handler 的宣告多一個選用的範例值，`user.register` 的 `emailDomain` 是 `example.com`）。試算結果疊在流程摘要上（略過的節點變灰、短缺的節點標紅），右欄保留明細。保留「試算」按鈕給「換了申請人再算一次」 |
| 儲存前的影響 | 儲存時的確認框：「進行中的 N 筆照送出時的版本繼續」「停用後新申請改由持有審批權限的人單關審核」。N 由 `GET /approval-flows/:type` 多帶 `inFlightCount`（`flow_id` 相同、`status = pending` 的筆數） |
| 實際運作 | 流程卡片與編輯頁顯示近 30 天：送出、核准、駁回、進行中的筆數，進行中的卡在哪一關、短缺幾筆。新端點 `GET /approval-flows/:type/stats`，開頁時即時彙總，不另做快照（D9） |

### 影響的模組

- 後端：`modules/approval`（`GET /approval-flows/:type` 多帶 `inFlightCount`、`requiredPermissions`；`GET /approval-flows/:type/stats`）、`modules/user`（`flow.fields` 的 `example`）。無新表。
- 前端：`features/approval-flow`。結果節點的句子沿用 `features/approval` 的 `APPROVAL_OUTCOME_KEY` 不行（feature 之間不 import）：流程設定另有自己的對照，或把對照搬到 `core/`。
- 權限：不新增權限鍵。

## 開放問題

1. 範本是否需要租戶自訂（存成資料）？
   - **結論：這一版只有內建範本（D6）。** 每個類型最多一個流程（§10.2 D1），設定一次就很少再從頭來；範本的目的是「第一次不要面對空白表單」。
2. stats 的時間範圍與快取：即時查詢、還是由背景工作每小時彙總？
   - **結論：開頁時即時查詢近 30 天，不做彙總（D9）。** 審批的量遠小於租戶用量那種全租戶的計數；實作時以 seed:dev 量測一次，慢了再加索引或改快照。

## 設計決策

| # | 決定 | 理由 |
| --- | --- | --- |
| D6 | **流程範本是前端內建常數**，依 `requester` 與 `assigneeKinds` 過濾 | 目的只是避開空白表單；不需要資料表與權限 |
| D9 | **流程的實際運作即時查詢近 30 天**，不做快照 | 量小、只有設定者會看；先量測再決定要不要優化 |
