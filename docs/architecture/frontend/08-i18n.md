# 前端 08 — 國際化

## 1. 目標

| 項目     | 決定                                                            |
| -------- | --------------------------------------------------------------- |
| 支援語系 | `zh-TW`（預設）、`en-US`                                        |
| 函式庫   | i18next（**不用** react-i18next，自寫薄 hook）                  |
| 來源格式 | JSON，隨原始碼進版控                                            |
| 載入方式 | **按 feature 分包，隨路由載入**                                 |
| 語系偵測 | 使用者偏好（後端） → localStorage → `navigator.language` → 預設 |

### 1.1 為什麼不用 react-i18next

react-i18next 會在每次語系變更時觸發大量重渲染，且它的 `Suspense` 整合與
TanStack Router 的 loader 機制重疊。我們的需求很單純：
「給我一個 `t()`，語系變了重渲染」。自寫的 hook 大約 40 行，訂閱 i18next 的
`languageChanged` 事件並觸發一次 re-render 即可。

## 2. 語系包的分包

```
app/locales/{en_US,zh_TW}.json                     全域（選單、通用按鈕、錯誤）
features/auth/locales/{en_US,zh_TW}.json           scope: 'feature-auth'
features/user/locales/{en_US,zh_TW}.json           scope: 'feature-user'
features/role/locales/{en_US,zh_TW}.json           scope: 'feature-role'
features/permission/locales/…                      scope: 'feature-permission'
features/account/locales/…                         scope: 'feature-account'
features/audit-log/locales/…                       scope: 'feature-audit-log'
plugins/features/*/locales/…                       各自的 scope
```

### 2.1 註冊（plugin 的 `onInit`）

```ts
await appContext.addResourceBundle(
  {
    [Languages.EN_US]: { [LanguageNamespace.TRANSLATE]: () => import("./locales/en_US.json") },
    [Languages.ZH_TW]: { [LanguageNamespace.TRANSLATE]: () => import("./locales/zh_TW.json") },
  },
  { scope: ROLE_LOCALE_SCOPE },
);
```

傳的是 **動態 import 的函式**，不是 JSON 內容。註冊只是登記「這個 scope 有這些
包可以載」，實際下載還沒發生。

### 2.2 載入（route 的 `loader`）

```ts
export const RoleListRoute = createRoute({
  path: "/role",
  loader: localeScopeLoader(ROLE_LOCALE_SCOPE),
  // …
});
```

`localeScopeLoader(scope)` 回傳一個 loader：

```ts
export function localeScopeLoader(scope: string) {
  return async () => {
    await loadLocaleScope(scope, i18n.language);
  };
}

const loaded = new Set<string>(); // `${scope}:${lang}`

export async function loadLocaleScope(scope: string, lang: string) {
  const key = `${scope}:${lang}`;
  if (loaded.has(key)) return;
  const importers = registry.get(scope)?.[lang] ?? {};
  await Promise.all(
    Object.entries(importers).map(async ([ns, importer]) => {
      const mod = await importer();
      i18n.addResourceBundle(lang, ns, mod.default, true, true);
    }),
  );
  loaded.add(key);
}
```

**效果**：`features/role/locales/*.json` 不在首屏 bundle 裡，第一次進入 `/role`
時才下載，且在頁面渲染 **之前** 就緒（loader 會 await），不會閃出原始 key。

### 2.3 切換語系時

`changeLanguage(lang)` 會：

1. `i18n.changeLanguage(lang)`
2. **重新載入所有已載入過的 scope 的新語系版本**（走同一個 `loadLocaleScope`）
3. 寫入 `localStorage` 與後端偏好（`PATCH /auth/profile`）

第 2 步容易漏：只切 i18next 的語系而不補載已進入過的 feature 語系包，那些頁面
會退回 key 或 fallback 語系。

第 3 步由 `features/account` 的 `useChangeLocale()` 負責（寫 `useLocaleStore` → `changeLanguage` → 同步帳號），
兩個入口共用它：

| 入口 | 位置 | 行為 |
| --- | --- | --- |
| 頂列語言按鈕 | `app/layouts/LanguageMenu.tsx` | 支援的語言（`SUPPORTED_LANGUAGES`）剛好兩種時按一下直接切到另一種（`language-toggle`）；超過兩種改成下拉選單（`language-menu-trigger`）；只有一種時不顯示 |
| 偏好頁 | `features/account/pages/Preference` | 下拉選單，另外顯示「已儲存」提示 |

語言名稱在 `LANGUAGE_LABELS`（`shared/constants/lang.ts`），一律用該語言自己的寫法、不翻譯，
看不懂目前介面語言的人才找得到自己的語言。

## 3. Key 命名

```
<domain>.<scope>.<name>
```

| 類別         | 範例                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| 全域通用     | `common.save` / `common.cancel` / `common.delete` / `common.confirm`    |
| 選單         | `menu.user` / `menu.role` / `menu.auditLog`                             |
| 錯誤碼       | `error.AUTHZ_FORBIDDEN` / `error.ROLE_NAME_DUPLICATE`                   |
| 權限名稱     | `permission.role.grantPermission` / `permission.resource.user`          |
| Feature 頁面 | `role.list.title` / `role.create.submit` / `role.detail.tab.permission` |
| Feature 訊息 | `role.create.success` / `role.delete.confirm`                           |
| 欄位標籤     | `role.field.name` / `user.field.email`                                  |
| 狀態值       | `user.status.active` / `user.status.locked`                             |

### 3.1 錯誤碼與權限名稱的特別約定

這兩類 key 對應 **後端定義的值**，但都不在前端組字串
（[`conventions/06-literal-strings.md`](../../conventions/06-literal-strings.md)）：

```ts
t(ERROR_MESSAGE_KEY.AUTHZ_FORBIDDEN); // 對照表：core/errors/errorMessageKey.ts
t(permission.nameI18nKey); // 後端回傳完整 key：permission.role.grantPermission
```

因此：

- 新增一個後端錯誤碼 → 必須同時在 `ERROR_MESSAGE_KEY` 與 `app/locales/*.json` 加 `error.<CODE>`
- 新增一個權限 → 必須同時加 `permission.<resource>.<action>`

沒加的話 `t()` 會回傳 key 本身（錯誤碼不在對照表時則拿不到 key）。`useErrorMessage()` 偵測到這兩種情況時
退回通用訊息，所以不會在畫面上顯示 `error.SOMETHING_WEIRD`——但這代表缺翻譯會
靜默降級，所以 **CI 有一支檢查**：掃描後端的 `ErrorCode` enum 與
`PERMISSION_SEED`，確認每一項在兩個語系檔中都有對應 key。

## 4. `useTranslation()`

```ts
// core/locales/useTranslation.ts
export function useTranslation() {
  const [, force] = useReducer((n) => n + 1, 0);
  useEffect(() => {
    i18n.on("languageChanged", force);
    return () => {
      i18n.off("languageChanged", force);
    };
  }, []);
  return {
    t: i18n.t.bind(i18n),
    language: i18n.language,
    changeLanguage,
  };
}
```

### 4.1 型別安全

透過 declaration merging 累積各 feature 的資源型別：

```ts
// 各 feature 的 plugin.ts
declare module "@/core/locales" {
  interface LocaleResourceMap {
    feature_role: typeof import("./locales/en_US.json");
  }
}
```

`core/locales` 把 `LocaleResourceMap` 展平成一個 key 聯集型別餵給 i18next 的
`CustomTypeOptions`，於是 `t('role.list.titl')` 會編譯失敗。

**en_US 是型別來源**，因此 en_US 是「規範」語系：先寫它，zh_TW 對齊它。
另有一支測試斷言兩個檔案的 key 集合完全相同。

## 5. 格式化

| 對象     | 作法                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 日期時間 | `dayjs` ＋ 使用者偏好的時區（`core/store/timezone`）。顯示格式由語系決定 |
| 數字     | `Intl.NumberFormat(i18n.language)`                                       |
| 相對時間 | `dayjs` 的 `relativeTime` plugin（稽核日誌的「3 分鐘前」）               |
| 複數     | i18next 的 `_one` / `_other` 後綴                                        |

```json
{
  "role.delete.confirm_one": "確定要刪除「{{name}}」這個角色嗎？",
  "role.delete.confirm_other": "確定要刪除選取的 {{count}} 個角色嗎？"
}
```

**時區**：後端一律以 UTC 儲存與傳輸（ISO 8601 帶 `Z`），前端在顯示的那一刻才
轉成使用者偏好的時區。任何把時區邏輯寫進 adapter 或 API 層的做法都是錯的。
