# 操作說明

一個任務一份文件，寫給要完成那件事的人。目前還沒有文件；新增時依下面的規則放。

## 放在哪裡

依讀者的角色分資料夾，與系統的兩個 app、兩種身分一致（[`../introduction/01-overview.md`](../introduction/01-overview.md) §2、§4）：

| 資料夾 | 讀者 | 在哪個畫面操作 | 例子 |
| --- | --- | --- | --- |
| `tenant-admin/` | 租戶的管理者（admin、super-admin） | `apps/backstage` | 設定多階段審批、匯入使用者、要求指定角色啟用 MFA |
| `platform-admin/` | 平台管理者 | `apps/platform` | 建立租戶、調整配額、全平台關閉某種驗證方式 |

一般成員自己的操作（設定 MFA、通知偏好）放 `tenant-admin/` 以外的新資料夾時，先在這張表加一列。

## 怎麼寫

- 檔名是任務本身，kebab-case：`set-up-approval-flow.md`、`import-users.md`。資料夾內不編號，任務之間沒有先後。
- 開頭一句話說明做完會得到什麼，接著列出 **需要的權限**（權限鍵與預設持有的角色）與前置條件（例如平台要先啟用某個功能）。
- 步驟用編號清單，一步一個動作，以畫面上的文字稱呼按鈕與欄位；需要截圖時在 `apps/e2e/tour/` 加 `scene`，輸出到 `../images/tour/`。
- 最後一節列出常見的錯誤訊息與處理方式；規則的理由只寫一句並連到規格，不在這裡重複。
