## 規則的強度

每條規則都標明它靠什麼守住，讓人知道哪些會被機器擋、哪些要靠 review：

| 標記     | 意義                                                           |
| -------- | -------------------------------------------------------------- |
| 🔒 工具  | 由 `tsc` / `oxlint` / `oxfmt` / 啟動檢查 / 測試強制，違反就失敗 |
| 👀 Review | 目前沒有工具擋，靠 code review 把關                             |

新增規則時：能用工具強制的就用工具強制，並把標記從 👀 改成 🔒。

## 撰寫慣例

- 規則要附 **理由**；沒有理由的規則會在第一次不方便時被打破。
- 規則要附 **正反例**，反例寫成 `❌ / ✅` 對照表。
- 已在 `architecture/` 詳述的機制只連過去，不在這裡重寫一次。
